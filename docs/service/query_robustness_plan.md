# 사용자 말투 질문 강화 계획 (2026-11-15 작성·test 뒤 갱신, 코드는 사용자 확인 뒤 시작)

본선에서 심사위원이 즉석으로 질문을 칠 수 있어, 일상 말투 질문에 강하게 만듭니다. **test는 이 개선과 관계없이 11/15에 고정한 설정(N3 / N3+VLM 재판별)으로 먼저 돌립니다.** 아래 개선은 모두 탐색적이고, 모델 채택 판정(vlm_model_plan.md 5장)에는 쓰지 않습니다.

## test 뒤 바뀐 점 (2026-11-15)

- **출발점**: test에서 사용자 질문(19개)은 N3 2/19·N3+VLM 3/19로 무작위 기댓값(3.0) 수준. 화면 글자·말 질의는 B3보다 나았지만 일상 말투는 못 잡음.
- **test 질의는 이제 쓸 수 없음**: test는 1회 실행으로 소비됐으므로 test 사용자 질문 19개는 고르기·조정에 쓰지 않음(나중에 「사후 참고」로만 보고 가능).
- **새 평가 질문에 쓸 수 있는 영상**: 시연 영상 53개 중 dev 8·test 8·LoRA 학습 20을 빼면 **새 시연 영상 17개**(기초연금 3·아이돌봄 3·청년 주거 4·장기요양 2·노인일자리 2·치매 3, 자막 없는 4개 포함).
- **비교 기준은 둘**: 지금 서비스 기본값 N3+VLM(n3_vlm)과 N3.
- **정책 우선 검색은 이미 일부 있음**: 지금은 질문에 정책 키워드(예: 「기초연금」)가 있을 때만 그 정책 영상 안에서 찾음. 개선의 핵심은 **정책 이름을 말하지 않는 질문**(「65세 넘으면 매달 나오는 돈」, 「애 봐주는 사람 부르는 거」)에서도 정책을 찾는 것. 정책 15개로 늘어 잘못 찾을 위험도 같이 커짐 → 정책 찾기 정확도를 따로 잼.
- **단계 카드는 검수된 것이 기초연금 영상 3개뿐**: (3)의 효과는 그 영상들에서만 드러남. 다른 정책은 단계 카드 검수를 먼저 하거나, (3)은 기초연금 질문에서만 따로 보고.

## 개선 세 가지

1. **정책 우선 검색**: 질문에서 공공데이터 정책을 먼저 찾고(지금의 키워드 → 정책명·요약·별칭으로 넓힘, 필요하면 MiniLM으로 질문 ↔ 정책 요약 유사도), 그 정책에 연결된 영상 안에서만 장면 검색. 정책을 못 찾으면 지금처럼 전체 검색. 정책 찾기 정확도를 따로 잼.
2. **질문 바꿔쓰기**: 일상 말투를 검색용 표현으로 바꾼 질문 2~3개를 만들어 원래 질문과 같이 검색하고 후보를 합침.
   - 후보 A: 규칙 사전(「뭐 챙겨가요 → 구비서류·필요 서류」, 「어디서 → 신청 장소·신청 방법」, 「얼마 → 지원 금액」 등). 빠르고 결과가 늘 같음.
   - 후보 B: 로컬 Qwen3-VL-4B(글만)로 바꿔쓰기 2~3개. 지연이 늘어남(질의당 약 0.3~0.6초 예상).
   - 합치기: 질문별 후보 점수를 영상 안에서 정규화한 뒤 최댓값(원래 질문 가중치 1, 바꾼 질문 0.8) — 결과 보기 전 고정.
   - **유출 방지**: 규칙 사전과 바꿔쓰기 프롬프트는 평가 질문(아래 2종)을 보기 전에 만들고, 예시 문장은 새로 씀.
3. **단계 카드 우선**: 질문 의도가 서류/신청서/자격/결과 중 하나면, 그 영상의 **검수 완료(reviewed)** 단계 장면을 후보 1순위로(초안 단계 카드는 쓰지 않음).

## 평가

| 평가 질문 | 개수 | 쓰는 영상 | 주의 |
|---|---|---|---|
| dev 사용자 질문 (기존) | 18 (정답 있음) | dev 영상 8개 | 이미 LoRA·결합 규칙 고르기에 쓴 질문이라 낙관적. 질문마다 그 영상 안에서 찾는 평가라 **정책 우선 검색(1)은 효과가 드러나지 않음**. dev01(기초연금 온라인 신청)은 단계 카드를 사람이 같은 영상을 보고 검수해서 **(3)의 효과는 따로 표시** |
| 새 사용자 말투 질문 | 약 30 (정책 이름 없는 질문 절반 이상, 영상에 답 없는 질문 몇 개) | 시연용 새 영상 17개만(평가 dev·test 영상, LoRA 학습 영상과 겹치지 않음. 자막 없는 4개 포함) | 아래 방식으로 새로 만듦 |

새 질문 만들기 (test 검수와 같은 방식):
- 별도 에이전트가 **영상 제목·채널·정책만 보고**(화면·자막은 안 봄) 어르신·청년·부모·가족 대신 묻는 사람 말투로 짧게 씀. 일부는 애매하게, 일부는 영상에 답이 없을 수 있는 질문(신청 기간 등) 포함.
- 정답 구간은 다른 에이전트가 초안 → **사용자 검수**(검수 도구 그대로, 약 30~40분 예상).
- 질문 파일은 개선 코드를 쓰기 전에 고정·커밋.

지표 (결과 보기 전 고정):
- **시스템 단위(시연과 같은 방식)**: 전체 시연 영상 세트에서 검색 → 1위 장면이 정답 영상·정답 구간과 IoU ≥ 0.3인 비율(R@1), 상위 3개 안(R@3), 시작 ±5초, 정답 영상이 상위 3개 영상 안에 있는 비율.
- **장면 단위**: 정답 영상 안에서만 찾았을 때 R@1 IoU≥0.3 (dev 18개는 이것만).
- 정책 찾기 정확도(새 질문), 정답 없음 질문은 「영상에 답 없음」 안내가 떴는지.
- 질의당 지연 p50·p95: 기본 결과 한도 1초 유지(바꿔쓰기 B 포함 시 확인).

비교 (같은 질문으로, 각각 VLM 재판별 있음/없음):

| 설정 | 내용 |
|---|---|
| 기준 | 지금 N3+VLM(서비스 기본값)과 N3 |
| +1 | 정책 우선 검색 |
| +2A / +2B | 질문 바꿔쓰기(규칙 / LLM) |
| +3 | 단계 카드 우선 |
| 전부 | 1 + 2(나은 쪽) + 3 |

고르기: 새 질문 시스템 단위 R@1 최대, 기준보다 dev 18개 R@1이 3개 넘게 떨어지면 탈락, 기본 결과 p95 1초 넘으면 탈락. 새 질문 30개뿐이라 ±3개는 잡음 수준으로 보고 보고서에 그렇게 적음.
