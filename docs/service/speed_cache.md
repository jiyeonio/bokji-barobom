# 서비스 속도 개선: 장면 정보 미리 만들기·질문 캐시 (2026-11-15)

> 서비스 속도 개선 기록입니다. test·제안서 숫자는 기존 고정 설정 기준이며 이 변경과 무관합니다.

## 1. 장면 정보 미리 만들기 — 만들었지만 배지 판정에는 쓰지 않음

- 영상 등록(색인) 때 장면(자막 덩어리 10~16초)마다 Qwen3-VL-4B로 **화면 종류·화면 글자·화면 설명**을 만들어 DB(`<WELFARE_DATA_DIR>/demo/scene_info.sqlite`, 표 `scenes`)에 저장: 53개 영상, 장면 1,451개 (`backend/scripts/build_scene_info.py`).
- 이 정보와 질문의 유사도(파인튜닝 MiniLM)로 배지를 바로 정하는 규칙을 dev 질의 102개(실시간 VLM 배지를 기준 답)로 맞춰 봤지만, **바로 정한 배지가 VLM과 95% 이상 같은 문턱이 없었습니다**(`backend/scripts/calibrate_badges.py`). VLM이 「화면에서 확인됨」이라 한 장면과 「확인 안 됨」인 장면의 점수 분포가 거의 겹침(중앙값 0.53 vs 0.48). 또 dev 질의 102개 중 12개는 VLM 재판별이 1위를 바꿔, VLM을 건너뛰면 순서도 달라집니다.
- 그래서 **빠른 배지(`BADGE_MODE=fast`)는 끄고(기본 `vlm`)**, 장면 정보는 DB에 남겨 둡니다(검색 보조·기관용 화면 등에 쓸 수 있음).

## 2. 시연·추천 질문 캐시 — 적용

- 시연 질문 8개 + 장면 콕 집기 후보를 지금 설정(n3_vlm, 실시간 VLM 배지)으로 미리 계산해 캐시(27개, `backend/scripts/precompute_cache.py`, 같은 DB의 표 `query_cache`). 키는 질문·정책 맥락·설정·시연 목록과 정책 정보 판 — 영상이나 정책이 바뀌면 자동으로 무효.
- 서버는 `QUERY_CACHE=on`으로 띄움. 캐시에 있는 질문은 VLM 확인을 기다리지 않고 **배지까지 바로** 나옴(응답 수 ms). 시연 질문 8개의 1위·배지·안내·시청 화면의 찾은 장면이 캐시 전과 같음을 확인.
- 캐시에 없는 질문은 지금처럼 기본 결과(약 0.5초) → VLM 확인 뒤 배지 갱신(약 4초).
- **주의**: 캐시된 질문은 「AI가 화면 확인 중 → 화면에서 확인됨」 배지 변화가 보이지 않습니다(처음부터 확인됨). 시연에서 배지 변화를 보여 주려면 캐시에 없는 질문을 쓰거나 서버를 `QUERY_CACHE=off`로 띄웁니다.
